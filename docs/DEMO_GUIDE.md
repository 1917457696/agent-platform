# 临床学习与问诊训练 Demo Guide

## 30 秒介绍

原来的系统主要解决 AI 与患者对话的问题，但面向医学教育，仅仅让 AI 给答案价值有限。因此我把它升级成了一个临床学习与问诊训练平台：学员先选择结构化病例，AI 扮演患者并逐步透露信息；学员结束问诊后提交训练，系统根据关键病史覆盖、风险信号和问诊路径生成评分、遗漏问题、原因解释和下一步学习建议。AI 不替代教师或医生，而是把练习、反馈和复盘变成可重复的训练闭环。

## 3 分钟项目介绍

### 为什么做

医学学员常见的问题不是完全没有知识，而是不知道问什么、先问什么，以及遗漏的信息为什么重要。普通聊天机器人会直接给结论，学生容易被答案带着走，无法验证自己的问诊过程。

### 产品设计

训练中心提供胸痛、咳嗽、发热等结构化合成病例。学员选择病例后扮演医生，AI 扮演患者，只根据学员问题逐步返回对应信息。结束后生成训练报告，包含问诊完整度、关键症状覆盖、临床思维、风险意识、遗漏问题、解释和临床思维时间轴。

### 技术架构

现有问答仍使用 React + FastAPI + Agent/RAG + SSE。病例训练 Demo 使用前端确定性病例状态和规则评分，确保现场稳定；真实模型问答和课程 RAG 仍保留。后续可把病例状态、评分规则和报告接口迁移到服务端，接入用户与训练历史。

### AI 的作用

AI 负责患者角色表达、课程资料检索、自然语言反馈和复盘草稿；结构化病例、关键问题覆盖、危险信号和评分基础由规则控制，避免让模型自由编造病例事实或随意给分。

### 最大亮点

产品从“问 AI 得答案”变成“主动问诊 → 提交判断 → 获得反馈 → 复盘薄弱点 → 再次训练”。它衡量的不只是回答是否正确，还关注学习者如何获取证据和组织临床思维。

## Demo Golden Path

1. 进入 `http://127.0.0.1:8001/`，滚动到中医教培工作台。
2. 点击“进入病例训练”，默认选择“胸痛 · 急性风险识别”。
3. 说明“你扮演医生，AI 扮演患者”，读取患者首句，不展示完整标准答案。
4. 输入：`疼痛在哪里、是什么性质、持续多久，活动和休息有什么关系，有没有放射到左肩或大汗，既往有高血压吗，是否过敏以及家族史如何？`
5. 在“初步判断”框中填写判断、依据和仍需排除的风险，不让系统提前展示标准答案。
6. 点击“结束问诊并提交”。
7. 展示综合评分、四项维度、初步判断、遗漏项和“为什么重要”。
8. 展示 Clinical Reasoning Timeline 中的 ✓ 与 ⚠。
9. 收尾说明：当前病例与评分为演示实现，正式上线需要教师审核、脱敏数据和服务端训练记录。

## 技术亮点问答

### 怎么展示一次运行到底经过了哪些节点？

工作台上方的“本次运行 · 实时记录”会在每次真实问答或本地陪练后更新。它展示安全护栏、主控分流、知识检索/工具、流式回答的节点路径，并显示总耗时、Token 用量和观测方式。供应商没有返回精确用量时，页面会明确标注“估算”，不会把估算冒充账单数据。当前默认是本地 Trace；生产环境可以把同一事件结构接入 LangSmith 或 Langfuse。

### 能力底座和运行路径为什么可以点击？

能力卡片会打开“输入—输出—边界—怎么查看”的详情；运行路径的四个节点会展开具体职责和当前项目中的验证方式。这样面试时可以从产品概念直接跳到实现证据，而不是只展示静态宣传文案。

### 为什么不是普通聊天机器人？

普通聊天机器人以回答为终点；训练平台以学习行为为对象，要求学员先主动问诊，再提交训练，最后根据过程而非单句答案反馈。

### 为什么使用结构化病例？

结构化病例可以固定患者事实、关键问题和危险信号，使每次训练稳定、评分可解释，也避免模型随机生成互相矛盾的患者信息。

### 为什么使用 Rule + LLM 混合评分？

规则适合判断是否覆盖关键问题、是否触发 Red Flag；LLM 适合评价提问质量、顺序和表达。两者分工比让模型直接输出一个 82 分更可追溯。

### 如何避免 AI 胡编病例信息？

病例事实放在结构化状态中，患者 Agent 只能从对应字段和已允许的回答模板中返回信息；无法匹配的问题返回“不确定”，不自由创造病史。

### 如何评估问诊完整度？

把病例的核心维度定义成可检查的标签，例如胸痛的位置、性质、时长、诱因、放射、呼吸困难/大汗、既往史和用药；按命中的维度计算规则分，再由复盘解释。

### 如何设计 Clinical Reasoning Timeline？

把每个学员问题归入病例维度，按消息顺序记录。已覆盖显示 ✓，遗漏显示 ⚠，低价值追问标记为低价值，帮助学员看到自己的问诊路径。

### 如何扩展成 OSCE 平台？

增加标准化站点、限时、评分量表、教师创建病例、语音输入和多维度评测；当前 Demo 已经提供病例状态、训练消息和报告的最小闭环。

## 面试官可能追问

1. **为什么先做病例训练？** 因为它同时验证学员价值、课程内容和教师审核，范围比全能问答更可控。
2. **问诊结束如何确定？** 当前由学员点击提交；正式版本可增加核心维度覆盖率、风险检查和最短对话轮数门槛。
3. **学生换一种表达怎么办？** 先做同义词和关键词归一化；正式版本加入意图分类和人工审核样本。
4. **为什么不用纯 LLM 评分？** 纯 LLM 的分数不稳定且难解释，规则负责可验证事实，LLM 负责开放式质量评价。
5. **评分怎么保证公平？** 固定病例、维度和评分规则；不同表达映射到同一标签；保留原始对话供教师复核。
6. **Agent 会不会泄露标准答案？** 训练模式只返回患者信息，不返回诊断和评分标签；报告在提交后生成。
7. **如何防止幻觉？** 结构化病例限制事实来源；RAG 回答必须带课程来源；个人诊疗、处方和剂量走安全闸与人工审核。
8. **病例数据从哪里来？** Demo 使用合成病例；正式上线由中医教师审校、脱敏并标注关键问题和教学点。
9. **真正用于医学院校还缺什么？** 教师量表、伦理与隐私流程、脱敏数据、服务端权限、可追溯评测和课程版权授权。
10. **如何评估学习效果？** 比较训练前后关键问题覆盖、风险识别、教师评分和重复错误，不把一次模型分数当成临床能力证明。
11. **如何做多轮记忆？** 将已采集病史、未覆盖维度和当前病例状态放进结构化 session；不把全部历史无限拼接给模型。
12. **如何降低 Token 成本？** 先规则路由和缓存课程 FAQ，只把必要病例摘要、最近对话和检索片段交给模型。
13. **如何支持上千学生并发？** 服务端拆分会话状态、模型调用和报告生成，使用队列、限流、缓存和异步任务；当前 Demo 尚未声称具备生产并发能力。
14. **如何做病例难度分级？** 由关键维度数量、Red Flag 数量、信息隐蔽程度和允许提示次数组合定义。
15. **如何接入医学指南？** 经教师和医学专家审核后分版本进入 RAG；回答带文档版本和出处，不把指南直接变成个人处方。
16. **如何保护患者隐私？** Demo 使用合成数据；正式系统需要脱敏、最小权限、加密、审计、删除策略和服务端授权。
17. **如果给你三天还会做什么？** 增加学员初步判断提交页、教师审核页、更多病例和离线黄金集回归。
18. **如果正式上线还缺什么？** 账号与训练记录、内容管理、教师审核、模型监控、错误反馈、权限体系和部署运维。
19. **AI 教练应该直接提示答案吗？** 默认只给方向性 Hint，例如提示关注疼痛与活动关系，避免替学员完成训练。
20. **一个人能不能做完？** 我可以负责 AI 应用层和 MVP 闭环；正式 App、数据、运维、医学审核和规模化需要团队协作。

## 安全边界

本系统用于医学教育与临床思维训练，不用于真实患者的诊断或治疗决策。使用“可能”“需要考虑”“训练中应关注”，不输出“患者一定患有”、处方、剂量或停药建议。
