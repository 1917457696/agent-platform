## 可以直接复用的能力

1. 复用当前医疗知识子图作为 AI 课程导师的 RAG 底座。
2. 复用当前病例状态和患者 Agent 作为 AI 病例训练模块。
3. 复用 SSE 和现有前端工作台，先用 Web/H5 验证，不先重构 App。
4. 复用规则护栏、来源引用、教师审核提示和 Trace 结构。
5. 复用会话级凭据隔离和短期记忆窗口，后续替换为账号级服务端会话。

## 今天可以实现的功能

在已有代码上，单日可稳定完成一个固定主题的 Demo：

- 展示一章中医课程的 AI 讲解；
- 固定资料问答并展示来源；
- 生成 3—5 道固定/模板化练习题；
- 进入一套外感咳嗽医案；
- 学员主动提问并提交初步判断；
- 生成覆盖、遗漏、风险和复习建议；
- 触发处方请求时转教师审核；
- 用截图或 Trace 展示节点和结果。

## 需求不够时的推进方式

客户当前没有提供完整课程、明确用户角色、评测量表、App 接口或验收指标时，不把这些缺口假设成已解决。先完成“场景访谈 → 内容授权 → 一个课程主题 → 一套医案 → 一组指标”的最小确认，再开始开发。

默认选择的首个闭环是：课程 AI 助教 → 章节练习 → 外感咳嗽医案 → 训练反馈 → 推荐回看章节。缺少真实资料时使用演示资料和合成病例，并在页面和现场讲解中明确标注。

## 不能做什么，以及如何解决

| 当前不能直接做 | 原因 | 当前解决办法 | 正式产品方案 |

| 真实课程 AI 导师 | 缺真实课程原文、授权和章节映射 | 使用固定的中医演示资料 | 课程上传、解析、知识单元审核和版本管理 |
| 长期能力画像 | 缺长期训练数据和教师量表 | 展示单次训练报告 | 服务端保存多次训练，结合教师校准 |

| 自动诊疗、处方、剂量 | 存在医疗安全和合规风险 | 安全闸、拒答和人工审核 | 仅保留合规的教学解释与医生/教师审核流程 |
| 学习效果承诺 | 没有基线和对照数据 | 先定义指标并记录基线 | 小范围试点后比较前后测、完成率和教师采纳率 |

## 正式产品实现方式

1. 内容侧：视频转写、文档解析、知识单元标注、老师审核和版本管理。
2. 数据侧：PostgreSQL 保存用户、课程、章节、训练、报告和教师审核；对象存储保存原始文件。
3. 检索侧：课程/老师/租户隔离的向量库 + BM25，回答带章节和版本出处。
4. 训练侧：病例状态机、教师量表、规则评分、模型解释和人工复核。
5. 推荐侧：根据错误知识点映射课程章节、练习和下一次病例。
6. 产品侧：学员端、教师端、机构管理端和 App/企微 API。
7. 治理侧：权限、审计、脱敏、版权、成本、模型质量、告警和数据删除。

## 如果给 1 个月应该如何建设

### 第 1 周：场景和内容

访谈讲师、班主任和学员，选择一个高频课程主题；完成资料清点、版权确认、知识单元和病例量表。

### 第 2 周：内部 MVP

完成课程导师、来源引用、章节练习、一套病例和教师审核闭环；建立黄金评测集。

### 第 3 周：试点与数据

在一个训练营小范围试用，采集答疑时间、转人工、采纳率、练习完成率和错误分布。

### 第 4 周：迭代与接入

修复 Bad Case，增加账号/权限/训练记录设计，和 App 负责人确定接口、埋点、推送与发布方案。
